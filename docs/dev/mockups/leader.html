R-UI · where the verbs live

The Leader Key

Find binds no letters — every printable character is search text, and that is the point of the surface. So as the verb set grows there is nowhere obvious to put it. Three editors solved exactly this problem on exactly this constraint, and the answer they converged on is not more keys: it is one prefix, a panel that teaches, and a command line for the long tail.

What they teach

Six mechanisms worth stealing, and what each becomes here.

The leader, and mnemonic groups

Spacemacs · Neovim convention

Every binding hangs off SPC, grouped by noun — SPC f is files, SPC b buffers, SPC p projects. Nothing competes with typing because the leader only means "leader" when you are not typing.

Here: one prefix, groups named after the things dossier has — filter, shelf, bundle, review, export.

which-key — the panel that teaches

Spacemacs · which-key.nvim

Press the leader, pause, and a panel lists what the next key can be. You never memorise; you read. Fast users beat the delay and never see it at all.

Here: the single most valuable import. It means new verbs cost nothing in memorised keys, and on a phone — where nobody has muscle memory — the panel is the interface.

Transients — a menu that holds state

Magit · transient.el

A popup of a prefix, its infixes (toggleable arguments, drawn as checkboxes that persist) and its suffixes (the actions). Temporary chrome that vanishes when you are done.

Here: our filters are infixes, not verbs. A checkbox shows on and off — which is the exact problem a status chip cannot solve, because a chip only exists once the filter is on.

M-x, and :

Emacs · Vim

The long tail has no key at all. It has a name, and the name is searchable. Nobody binds "sort by expiry ascending"; they type enough of it.

Here: confirms the instinct — rare verbs are commands. The important part is that the command list is fuzzy-searchable, or it is a manual, not an interface.

One picker, reused everywhere

Telescope · Vertico · Helm

Files, buffers, symbols, git branches, commands — all the same widget: a filter line, a list, Enter runs it. Learn it once, use it for everything.

Here: Find is that widget already. The command list should be the same rows with the same matcher, not a new kind of thing.

Modes — and what they cost

Vim · Helix

Modes free the whole alphabet. They also demand a permanent mode indicator, an escape discipline, and a user who knows which mode they are in before they touch anything.

Here: rejected — Esc is already the peel, and "type to search" stops being true the moment there is a mode where it isn't.

What is actually free

The reason a leader is even possible: a query never usefully begins with a space, so Space on an empty query is unclaimed. Mid-query it types a space, exactly as it does now.

That "empty query" condition is the whole trick, and it is the same one Spacemacs uses — SPC is a leader in normal mode and a space in insert mode. We get the same split without modes, because the query itself is the mode: empty means you are not typing yet.

A Leader sheet recommended base

Space on an empty query raises a which-key panel over the bottom of the list. Esc closes it.

Groups are nouns, not verbs, so the sheet stays the same size as the app grows — new things go inside a group. Nothing is memorised on first use and nothing is memorised on the hundredth either, because the sheet is always one key away.

On a keyboard it appears after a short delay, so SPC f x typed quickly never flashes a panel. On touch it appears at once: there is no muscle memory to preserve and the panel is the affordance.

B Transient toggles inside it recommended

A group whose contents are state, drawn as checkboxes — magit's infixes, exactly.

This is the piece that earns its keep beyond discoverability. A checkbox shows off as well as on, so the filter has a visible way in and out. The status chip in the truth row could never do that — it does not exist until the filter is already on.

It also gives the keyboard shortcut a home that teaches it: ^x sits beside the row it fires, so the sheet is where you learn the accelerator you will later use instead of the sheet.

C Type in the sheet and it becomes a picker recommended

Don't know the group? Type. The sheet filters to matching commands and shows the chord that would have got you there.

This is Telescope and M-x folded into the same object, and it removes the usual leader complaint — that you must know the tree to use it. You either know the chord or you know the word.

It costs nothing new to build: the same rows, the same fuzzy matcher, the same Enter. And every result teaches its own shortcut, which is how a user graduates from searching to typing SPC f x.

D The command line alone

: with completion, and no leader at all — the plan as it already stands.

Right for the long tail and wrong as the only route. A command line answers "what is this called", never "what can I do here" — you cannot browse it, so nothing is ever discovered, only recalled.

Keep it. It is the third tier, and it is where anything used less than weekly should live. It is also the only tier that scales to a hundred verbs without a single new key.

E Modal not recommended

Vim's answer: a normal mode where letters are verbs, i to type, Esc back.

It buys the entire alphabet. It costs the thing the app is for: find-fast means you open it and type, and a mode where typing does something else breaks that on the very first keystroke.

It also puts a second job on Esc, which already peels four layers and arms the quit, and it needs a permanent mode indicator in a header that is carrying counts.

The same object on a record

Three tiers, and what goes where

The rule you named, made concrete: a key for what you do every time, a leader chord for what you do sometimes, a command for the rest.

A dedicated key

used every session, muscle memory earns its place
  • Enter open
  • → ← record in, record out
  • ↑ ↓ move
  • Esc peel
  • ^x expiring
  • ^t scan text

A leader chord

weekly, or needs its state shown
  • SPC f filters — a group of toggles
  • SPC s shelf
  • SPC b bundle
  • SPC r review the unfiled
  • SPC e export
  • SPC g go to

A command only

rarer than weekly, or dangerous enough to spell out
  • :doctor
  • :reconcile
  • :export csv
  • :reset
  • :service install
  • :dedup

Two things fall out of the table. The chord is a shortcut for a command, never a separate thing — SPC f x and :expiring run the same code, and the sheet shows the chord beside the name so the two stay tied. And a destructive verb should be spelled, not chorded: :reset is safer typed out than sat one slip away from SPC r.

What I would build

A + B + C — one sheet that teaches, holds state, and filters. Space on an empty query raises it; groups are nouns; filters inside it are checkboxes rather than verbs; typing turns it into the command picker, using the list widget Find already is. : stays as the third tier for everything rarer.

It costs no permanent rows, which is the whole reason it beats a bar — the argument that deleted the action bar deletes any replacement for it too. And it is the same mechanism on Find and on a record, so R4 gets its verb surface for free rather than inventing one.

On touch, Space is not reachable with the keyboard down — so the sheet needs a tap target too. The obvious one is the same header count zone extended: tap the app name to open the sheet. That is one more pressable thing than the current design has, and it replaces the need for anything else ever being added to the bottom.

Open, and worth deciding before it is built. Does the sheet appear over the list, or does the list shrink to make room? Over is cheaper and matches every editor that does this; shrinking avoids hiding the row you were looking at.

And what does Space do when the query is empty but a filter is live — leader, or is that state "typing"? I would say leader: the query is what decides, not the filters.
