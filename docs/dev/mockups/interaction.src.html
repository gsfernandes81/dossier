How It Answers

The layout is the easy half. What makes the app feel like itself is a handful of rules about what keys do, applied without exception — most of them paid for by about twenty pull requests of getting it wrong in v2. These are the ones the rewrite carries over intact.

Five keystrokes, cold acceptance

The benchmark the whole design answers to: from a dark phone screen to the file open, in five keystrokes and under a tenth of a second. On the real phone the app is interactive 6.2 ms after launch — the typing is now the slow part, by three orders of magnitude.

ds c o c ⏎   — launch, three letters into the search that is always already focused, Enter.

inv 1

The first character is kept. There is no “press / to search”: a printable on the list is the search, and it starts with the letter you pressed.

why

This is why no letter is bound on the base surface, and why every panel moved behind :. One rule, enforced everywhere, rather than a table of exceptions.

Escape peels one layer inv 3

Every press removes exactly one thing, in a fixed order, and it takes two consecutive presses at the base state to quit. This is not tidiness — on Termux the keyboard's own dismiss key sends Escape, so an app that quits on a stray Escape is an app that quits while you are reading it.

esccloses the edit in progress — twice discards it
escleaves command mode, back to search
escclears the search text and its filter chips
escpops the surface — detail, review, bundles — cursor preserved
escat the base state: arms, and says so in the footer
escquits — but only immediately after the one above; any other key disarms it
verified

Tested on the phone in R0.2: dismissing the soft keyboard with Escape does not quit the app.

always

ctrl+c and ctrl+q quit cleanly from anywhere, and nothing ever binds over them.

Touch, and the keyboard problem inv 6

Termux only raises its soft keyboard on a tap when mouse reporting is off — and no escape sequence, API or property exists for an app to raise it directly. So the ⌨ control drops mouse reporting for exactly one tap. Four steps, and the user sees none of them.

tap ⌨

The app turns off SGR mouse reporting and says so quietly in the bar.

tap anywhere

With reporting off, Termux treats it as a plain tap and raises the keyboard.

type

Characters land in the search bar, which never lost focus.

first key restores it

Mouse reporting comes back on, so taps select rows again. No mode to get stuck in.

R0.2

Termux has no function keys. That makes the on-screen ⌨ button the only route to this — not a convenience. It is why the touch action bar exists at all.

#4302

Mouse mode also blocks the terminal's own scrollback, so the app owns scrolling. Verified on the phone: drags scroll the list.

inv 6

First tap selects, a second tap on the same row opens. No double-tap timing — timing gestures are miserable on a laggy terminal.

Colour is never alone §6

Every status carries a glyph as well as a colour, so the list reads the same in monochrome, under NO_COLOR, and on a phone font with no icon set. R0.2 confirmed the phone has no Nerd Font glyphs at all — which turns the ASCII-first rule from a preference into a requirement.

When there is no room §4

Two layout states, and a floor. Below 38×12 the app says so plainly instead of rendering a broken frame — a notice you can read beats a layout you cannot.
