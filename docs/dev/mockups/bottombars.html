Two Chips and a Quiet Row

The six directions on the previous page were drawn for a thumb with no keys at all. That thumb does not exist: Termux pins an extra-keys row above the terminal, and with arrows, Esc, Enter and a held CTRL already under it, the action bar's charter — verbs a thumb has no other way to reach — collapses to two toggles. Two toggles do not earn a row. They earn being pressable where their state is already drawn.

Three consequences, and they are the whole revision. ▶ opens the detail pane — so a → Detail button is the ⏎ Open mistake again, a cell spent on a key the thumb already has. Swipe-up on CTRL is Esc, and Esc twice is quit — so the previous audit's two "orphan" verbs were never orphans on this device. Enter is a swipe away, so opening never needed a button either. CTRL is a held modifier, and composes with ALT — so ctrl+x and ctrl+t are ordinary two-finger presses whenever the soft keyboard is up. With it down there is no letter for the modifier to take, and those two are what is left.

The Stock Termux column is why the in-app affordances do not simply disappear. A fresh install ships Esc, Ctrl and all four arrows — so the minimum this design assumes is already satisfied out of the box — but it has no KEYBOARD key and no ENTER. Tapping the field to raise the IME, and tapping a row twice to open it, are the only paths a first-run device has, and both stay.

C′ Two chips and a quiet row recommended

The bar row is deleted and given back as a gutter that is blank until the app has something to say.

The chips reserve their state column whether or not the dot is lit, so a chip never changes width when it is toggled. A row that reflows on a tap is a row whose next tap lands somewhere else.

The → detail hint sits in the truth row's slack, dim: information, not a control. It teaches the key that ▶ sends.

Esc, armed

Quit is two Escs, and swipe-up on CTRL is Esc, so quit is thumb-reachable — clumsily, but it exists, and the armed state announces itself in the gutter rather than in a status line nobody reads.

This row is also why the IME's back-button dismissal is still a hazard: it sends a real Esc. The arming protection stays regardless of the key row.

D′ The toggle dock

Same three rows, but the two toggles become two-row slabs beside a shortened field — targets the equal of the field itself.

^x Expiring is exactly eleven columns, so the field takes 21 and the two slabs take 11 each with single-column gaps: 45 on the nose. The second slab row carries the state dot.

Costs nineteen typable columns, which is fine for the find-fast queries this surface is built around, and adds an internal boundary between the field and the first slab that a wide thumb can straddle.

B′ The two-cell bar

The conservative retreat: keep a bar row, put the two surviving toggles on it, and lose the gutter.

Only if both others fail. This buys width over the chips — 21 columns against 13 — and nothing else. The cells are the same one row tall, so if the chips miss because they are short, this misses too; and it spends the whole message row to do it.

The recommendation, where it is tested

Twelve documents at the phone size, the same frame with no colour at all, the terminal floor, and the desk layout where the chips become mouse targets.

The Termux keys to document

Minimum — what the interaction model assumes

This is a subset of Termux's own default row, which is the sentence that matters: a fresh install is already fully operable, and nothing needs configuring before the app works.

# ~/.termux/termux.properties — the stock default already covers this
extra-keys = [[ \
  {key: ESC}, \
  {key: CTRL}, \
  {key: LEFT}, \
  {key: UP}, \
  {key: DOWN}, \
  {key: RIGHT} \
]]
KeyWhat it serves
ESCThe peel — clear the query, pop the surface, clear a filter, arm, quit. The single most-pressed key in the app.
CTRLThe one-shot latch. With the IME raised, CTRL then x/t/q reaches both filters and quit.
LEFT / RIGHTThe record pair — → opens the detail pane, ← closes it.
UP / DOWNMoving the cursor without raising the keyboard. Long-press auto-repeats, which is how you cross a long list.

Recommended — the row this design was drawn against

Verbatim from the phone the layout was measured on.

extra-keys = [[ \
  {key: CTRL, popup: ESC}, \
  {key: ALT, popup: TAB}, \
  {key: SPACE}, \
  {key: LEFT, popup: HOME, display: "◀"}, \
  {key: UP, popup: PGUP, display: "▲"}, \
  {key: DOWN, popup: PGDN, display: "▼"}, \
  {key: RIGHT, popup: END, display: "▶"}, \
  {key: KEYBOARD, popup: ENTER} \
]]
KeyWhat it serves
CTRL · ESCThe latch for ^x/^t/^q; swipe up for the peel, and twice to quit.
ALT · TABNothing in dossier today. Tab is the candidate for cycling review tabs later, and this row is why Tab is a safer future binding than any new control combination.
SPACEMulti-word queries without reaching into the IME's bottom row.
◀ ▲ ▼ ▶Cursor, paging (swipe up), and the detail pair. Long-press repeats.
KEYBOARD · ENTERRaise or dismiss the IME without touching the terminal surface, and open the highlighted document without raising it at all. Note this dismissal does not send Esc, unlike the Android back button — this row produces fewer stray Escs, not more.

Optional, and not urged

A second row of macros puts the two filters on the key row:

[{macro: "CTRL x", display: "exp"}, {macro: "CTRL t", display: "scan"}]

It works. It is also global to every Termux session, costs a document row's worth of screen height everywhere, and — the reason it does not replace the chips — a macro can send a verb but can never show its state. If you add it, the chips stop being your controls and go on being your state display, which is not the ⏎ Open class of duplication.

What I would build

C′ — no bar. Delete the action row, make the two state chips pressable, and spend the freed row on a gutter that is blank until the app has something to say. The bar was right when it was designed against a thumb with no keys; the device this runs on has eight pinned above the terminal, and the design should stand on that.

Three fixes ride along regardless of which direction wins: hints shed item by item rather than a line at a time, the bottom chrome goes inert while a record is pushed so a tap cannot filter a list you cannot see, and the desk layout gains the underline and the missing ^t scans hint.

Reachability, end to end: Expiring is chip / ^x / (planned) header-count tap; Scans is chip / ^t; Detail is ▶ or →, taught by the dim hint; Open is tap-tap or Enter, taught once in the gutter; Esc and quit are the key row, with the armed state in the gutter.

Check on the device before this is documented. Three mechanics here are drawn from Termux's documented behaviour, not from a measurement on this phone: that popup: fires on swipe-up while long-press auto-repeats, that CTRL latches one-shot into the next key from either the row or the IME, and that stock Termux's default row carries ESC, CTRL and the arrows. Each is a thirty-second check, and R0.2's rule was that we measure the phone rather than reason about it. One in-app note too: input.rs matches KeyCode::Right with no modifier guard, so ctrl+→ currently acts as plain → — harmless, but not deliberate.
