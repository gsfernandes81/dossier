The Bar, Four Ways

The search bar is two rows now and still doesn't read as a control — three dim rows stacked at the bottom of the screen give the eye no edge to land on. Four ways to fix that, each drawn at the real 45 columns, with what it costs and how it survives a terminal with no colour.

The problem as it ships today

Everything below the list is dim text on the same ground as the list. The block is twice as tall as it was, and it still has no boundary — height alone doesn't make a target legible.

rule

Colour is never the only signal — whatever is added has to read the same in monochrome, where hues collapse but reverse video, bold, dim and underline all survive.

rule

The terminal theme owns the palette. A fix that needs a specific background colour is a fix that breaks on somebody's Solarized.

rule

Twelve documents is the budget. Anything that spends a row has to be worth a document, every screen, forever.

Each drawn against the same four list rows, so the boundary — or its absence — is what differs.

The buttons become buttons — each label in its own reverse block — and the field keeps a single slab row beneath them. The two halves of the chrome stop looking like one another.

The most app-like, and the most assertive: four inverted blocks are a lot of ink for a surface whose job is to disappear behind a list.

Which one holds up whole screen · monochrome

D drawn full-height, then the same frame with every colour removed — the NO_COLOR reading is where a design that leans on hue quietly falls apart.

Side by side

OptionRowsMonochromeRisk
A · Slab none becomes reverse video — heavier a two-row inverted block can dominate a small screen
B · Rule one document identical none, beyond the row it spends
C · Field none identical — underline is an attribute subtle; may still read as thin at arm's length
D · Chips none chips get heavier, structure survives most ink on screen; buttons compete with the list

My pick is C, with D's chips on the buttons only. The underline puts the emphasis on the row your thumb is aiming at, costs no rows, and is the one treatment that looks the same on every terminal anyone will ever run this on. Making the four buttons chips at the same time gives the chrome two distinct textures without a second filled block.

If it still reads thin on the device, A is one line of code away — the slab and the underline are the same span, differently styled.

B is the fallback I would take only if both fail, because a document row is the most expensive thing on this screen.
