The Minibuffer

Emacs does not have a search box. It has one line at the bottom of the frame that becomes whatever is being asked right now, with a prompt that names the question — and the same line is where the program talks back. Vim's answer is the same shape: :, / and ? are prompts, and the prompt is the mode. Neither draws a box.

What the minibuffer actually is

The prompt names the question

Never a bare marker. Find file:, M-x, Switch to buffer (default main): — the prompt is read-only text inside the buffer, and it says what will happen to what you type.

Here: > says nothing, which is precisely why the field needs a placeholder telling you to type. Name the prompt and the placeholder is redundant.

The prompt is the mode

Vim's :, / and ? are three prompts on one line. You know what you are typing into by looking at the first column, and nothing else has to be drawn.

Here: find, command and picking-in-the-sheet are three questions that already share a row. The prompt can carry which.

It is also the echo area

When nothing is being asked, that same line is where Emacs says things. One place for "what I am telling you" and "what you are telling me", never two.

Here: the row under the field already carries flashes and esc again to quit. Emacs would call that its identity rather than an interruption.

Candidates go above it

Classic Emacs opens a *Completions* window; Vertico draws a vertical list of up to ten candidates directly above the prompt line, and moving the selection up to the prompt is how you keep your literal input.

Here: the leader sheet already sits above the entry line and already filters as you type. That part is done.

No box, ever

There is no border, no field, no underline. The prompt plus the cursor is the whole affordance — because a keyboard user is already looking at the cursor.

Here: the underline is not decoration, it is the typable texture and the touch target's boundary. Emacs never had a thumb to design for.

The count rides along

Vertico and Icomplete put the match count next to the input, not on a line of its own — the number belongs to what you just typed.

Here: the count is on the row below, which is a row that could be doing something else.

Where it is now

Four ways to make it a minibuffer

A Name the prompt recommended

Find: instead of >. Six columns, and it replaces fourteen: the invitation is redundant the moment the prompt says what it is, so the row gets shorter and clearer at once.

It still reads as a question once you have typed, which > coc does not. And it leaves room for the signpost that finishes on the chip.

B Drop the box not on a phone

Pure Emacs: prompt, cursor, nothing else. On a keyboard this is right — the underline is telling a keyboard user something they can already see.

On touch it costs two things at once. The underline is the settled typable texture, and it is the visible boundary of the tap target that raises the keyboard. Emacs never had a thumb to design for. Worth taking on the desktop layout alone, if anywhere.

C Fold the count in recommended

Vertico's move: 4/24 belongs beside what you typed, because it is the answer to it. That leaves the row below carrying only hints — and makes it honestly an echo area, whose default content happens to be a hint line.

The second specimen is the same row saying something. Nothing had to be displaced to make room, because saying things is now what the row is for.

D The prompt carries the question

Vim's : for a command; the sheet's breadcrumb as the prompt when you are picking inside it. One line, three questions, and the first column tells you which — so command mode needs no new chrome when it lands, and the picker stops being a special case.

Note the chip goes when the question is not "find": there is nothing to open a sheet from inside a sheet, and a command line is typed, not tapped.

What I would build

A + C + D. Name the prompt, fold the count in beside what you typed, and let the prompt change with the question. Keep the underline on touch — that is the one place Emacs's answer does not transfer, and it is not a close call: the box is the tap target.

The prize is not tidiness. It is that command mode arrives for free: when : lands there is nowhere new to put it, and the sheet's picker stops being a special-cased row and becomes the same entry line with a different prompt.

Your call on the word. Find: is what Emacs would write and what §1 calls the surface. Search: is more literal about what typing does. Filter: is the most accurate — the list is already there and typing narrows it — but it is the least like an invitation.

And whether it keeps a colon. Find: reads as a prompt; Find reads as a label; > stays available as a second glyph if you want the prompt to be short on the desktop, where the hint line is already teaching every verb.
