The Verb Audit

⏎ Open was a button for a gesture you already had, and it shipped anyway. This is every verb the Find surface offers, what invokes it by key and by thumb, and where it is taught — followed by the kinds of fault that turns up.

Revised. This audit was first written against a thumb with no keys. That thumb does not exist: Termux pins an extra-keys row above the terminal, and the phone this is built for carries CTRL·ESC, ◀▲▼▶ and KEYBOARD·ENTER on it. Two findings below are retracted because of it, and one new duplication takes their place.

The reachability column and every retraction are marked. Nothing else has changed — the duplications, the vanishing hints and the leaking stack are all still true, and none of them are fixed by a key row.

What is wrong

retracted Esc has no thumb

The entire peel machinery — clear the query, pop the surface, drop the filter, arm, quit — is keyboard-only. On a phone with no keyboard raised there is no way to clear a search or back out of a filter; the one key the whole interaction model rests on is invisible to touch.

This is a bigger hole than ⏎ Open was, and in the opposite direction: not a verb with two affordances, but a verb with none. Quit is the same story, though Android's task switcher makes it survivable.

Wrong. Swiping up on the key row's CTRL sends Esc, and stock Termux ships a bare ESC key. Twice is quit. Both "orphans" were reachable the whole time — the audit reasoned about the phone instead of looking at it, which is the exact failure R0.2 was run to avoid. It stays on the page rather than being deleted, because a retraction is more useful than a tidy list.

duplication → Detail is ⏎ Open again

A third of the touch bar is a cell for →. The key row has ▶, and so does stock Termux's default. It is the same fault as ⏎ Open, one round later: a button for a key the thumb already holds, spending a quarter and now a third of the only touch chrome there is.

Which leaves the bar's charter — a cell exists only for a verb a thumb has no other route to — satisfied by exactly two verbs, both of them toggles whose state is already drawn a row below.

duplication The next ⏎ Open is already scheduled

The layout plan says the header's counts are tappable and each names its command. The moment that ships, the bar's ^x Expiry cell duplicates a tap the header already gives you — the same mistake, and it is in the plan rather than in the code, which is why nobody has noticed it yet.

incoherence One toggle, two objects, two rows apart

The thing you press (^t Scans, reverse video) and the thing that says it is on ([scans], dim) are separate objects in separate rows in different textures. A user has to learn the mapping between them. The button also grows its • while the scan text is still loading, when the chip below is still honestly saying [scans…].

Worse, the dim chips sit inside the tap-to-type zone: tapping [scans] — a token about the scans toggle — raises the keyboard. Three kinds of object in two rows, one of which does something unrelated when pressed.

teaching gap The hints vanish exactly when they are needed

The hint is shown only if the whole string fits, and dropped entirely otherwise. One filter still fits. Two filters and the teaching disappears — at the moment the user has the most state live and the most reason to want a way back.

Verified on the running binary, not inferred: ctrl+x then ctrl+t at 45×28 leaves the row below empty of hints.

teaching gap The touch hint teaches keys to a thumb

The hint line on the touch layout reads ⏎ open · esc back · ^q quit — three keyboard verbs, shown to the one user who cannot press any of them. Meanwhile the gesture a thumb must learn — tap the selected row a second time to open it — appears nowhere at all, and has appeared nowhere since the ⏎ Open button left.

Half retracted. A thumb can press all three, from the key row — so the hints are not addressed to nobody, they are a legend for the row above the terminal, which is a reasonable thing for them to be. The second half stands unchanged: tap-to-open is still taught nowhere, and it is the one verb the key row cannot teach.

orphan ctrl+t is unteachable on the desktop

The keyboard layout has no action bar, and its hint line lists ⏎ open · → detail · ^x expiring · ^q quit. Content search appears in no desktop hint. The verb exists and is reachable only by prior knowledge — which is nearly excusable, since the desktop is where scan text is written, and nearly is not a design.

incoherence The stack metaphor leaks

When a record is pushed full-screen over the list, the bar is still drawn and its other two cells still act. Tapping ^x Expiry inside a record mutates a surface you cannot see — and a bare printable still edits the hidden query underneath.

incoherence Three buttons, three grammars

Detail swaps its label. Scans grows a dot. Expiring shows nothing at all and delegates its state to a chip in another row. One row, three conventions — and the word itself changes between Expiry (button), expiring (hint and chip) and :expiring (the planned command).

What this implies

Three of these are unconditional fixes whatever shape the chrome ends up in: hints must degrade item by item rather than vanishing whole, the Find chrome must go inert while a record covers the list, and the keyboard layout must teach every verb it has — starting with the underline its query row is currently missing.

The rest are structural, and they point the same way: a toggle should be one object that both shows its state and accepts a press, and a bar cell should exist only for a verb a thumb has no other route to.

Applied against the key row, that second rule empties the bar. Detail is ▶; Open is Enter or a second tap; Esc and quit are a swipe. What is left is ctrl+x and ctrl+t — two toggles, whose state this surface already draws. So the answer is not a better bar but no bar: make the state chips pressable and give the row back. The companion page works that through, with the termux.properties rows to put in the install notes.

And the finding that survived the revision intact: tap-to-open is taught nowhere. It is the one verb no key row supplies, and it needs a sentence somewhere the first time a row is selected.
